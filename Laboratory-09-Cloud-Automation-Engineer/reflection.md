# Mission Reflection: The Cloud Automation Engineer

This laboratory activity helped me understand how automation makes cloud management faster and more reliable. Managing hundreds of cloud servers manually requires a lot of time and effort. Automation allows administrators to perform repetitive tasks without running every command themselves. For example, a backup script can compress important application files and save them in a backup directory.

However, automation also has risks. A mistake in a script can damage files or affect many systems if it runs repeatedly. Before scheduling a script, administrators should test it carefully, check its commands, and make sure it only modifies the intended files.

Writing a Bash script is different from creating a Docker Compose YAML file. A Bash script contains commands that perform tasks in sequence, such as creating directories and compressing files. A Docker Compose file describes application services, their images, environment variables, ports, and connections.

Throughout this semester, my understanding of cloud computing has improved. I learned about cloud infrastructure, multiple cloud providers, containers, data storage, deployment, server monitoring, security, and automation. I also learned that cloud computing involves more than launching a server. It requires proper configuration, maintenance, protection, and documentation.

Among the different roles, I find the Cloud Automation Engineer role interesting because it reduces repetitive work and helps prevent human error. Creating a script and scheduling it with cron showed me how simple commands can become useful automated processes. This activity also taught me to verify the output instead of assuming that a script worked correctly.

Overall, this mission improved my confidence in using Linux commands and writing basic scripts. I now understand why automation is important for managing cloud systems efficiently and consistently.
