# Cloud Infrastructure Components

## 1. Compute Resources

Compute resources provide the processing power needed to run operating systems, applications, and workloads.

Compute resources are important because cloud applications require processing power to execute tasks. Cloud computing allows organizations to increase or decrease computing resources depending on their workload.

The CPU in the KillerCoda environment is used to execute Linux commands, run applications, and perform the activities required in this laboratory.

## 2. Storage Resources

Storage resources provide space for storing the operating system, applications, configuration files, and user data.

Storage is important because cloud applications need space to store and retrieve data. Cloud storage also allows organizations to increase their storage capacity as their data requirements grow.

The virtual disk in the KillerCoda environment stores the Ubuntu operating system, applications, and files needed to perform the laboratory activities.

## 3. Networking Resources

Networking resources allow computers, servers, applications, and users to communicate with one another.

Networking is important because cloud servers need to communicate with users, other servers, databases, and external services. A properly configured network also allows cloud resources to communicate securely.

The KillerCoda Linux environment uses network interfaces and IP addresses to communicate with other network resources and the cloud laboratory environment.

## 4. Operating System

An operating system manages computer hardware resources such as the CPU, memory, storage, and network interfaces. It also provides an environment for running applications and commands.

The operating system is important because cloud servers need an operating environment in which applications and services can run. Linux is widely used in cloud computing because of its stability, flexibility, security features, and powerful command-line tools.

Ubuntu allows me to interact with the KillerCoda cloud server through the Linux terminal. I used Linux commands to examine the CPU, memory, storage, networking, hostname, and operating system information.
