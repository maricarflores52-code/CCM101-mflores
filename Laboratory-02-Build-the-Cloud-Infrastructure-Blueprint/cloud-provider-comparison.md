## Comparison Table

| Infrastructure Component | AWS | Microsoft Azure | Google Cloud Platform |
|---|---|---|---|
| Compute | Amazon EC2 | Azure Virtual Machines | Google Compute Engine |
| Storage | Amazon S3 | Azure Blob Storage | Google Cloud Storage |
| Networking | Amazon VPC | Azure Virtual Network | Google Cloud VPC |
| Identity and Access Management (IAM) | AWS IAM | Microsoft Entra ID / Azure RBAC | Google Cloud IAM |

## 1. Which cloud provider offers the broadest range of services?

AWS is a strong choice for the broadest range of cloud services because it provides many options for computing, storage, networking, databases, security, analytics, and other technologies. Its large collection of services gives organizations many choices when building different types of cloud solutions.

## 2. Which cloud provider would you recommend for an organization that primarily uses Microsoft products? Why?

I would recommend Microsoft Azure for an organization that already depends heavily on Microsoft products. Azure works closely with Microsoft's ecosystem and provides services that can integrate with Microsoft technologies, identity management, and enterprise applications. Azure RBAC also allows administrators to control what users can do with Azure resources.

## 3. Which platform is widely recognized for Artificial Intelligence (AI), Machine Learning (ML), and Kubernetes services?

Google Cloud is a strong choice for AI, machine learning, and Kubernetes workloads. It provides Google Kubernetes Engine (GKE) for managing Kubernetes applications and offers various cloud services designed for data and AI workloads.

## 4. What similarities did you observe among the three cloud providers?

The three cloud providers offer similar fundamental infrastructure services even though they use different names. AWS, Azure, and Google Cloud all provide virtual computing, scalable storage, networking, and identity/access management. This means that the basic cloud architecture concepts can be applied across different providers.
