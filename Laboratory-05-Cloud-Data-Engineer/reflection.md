# Mission Reflection

This laboratory activity helped me understand why different types of storage are used for different purposes. Object Storage is appropriate for millions of photos because it is designed to handle unstructured files such as images, videos, and backups. Instead of treating the photos like a traditional computer hard drive, the files can be stored as separate objects within the storage system.

Docker made the MinIO deployment easier because the application could be started inside a container using a single command. The required ports and login information could also be provided through the command, reducing the amount of manual configuration needed before the storage server could be used.

A bucket is a container used to organize objects in an object storage system. During this activity, the bucket named `client-photos` was created to provide a location where the sample file could be stored and accessed.

Large companies can protect their object storage data by keeping additional copies and backups of important information. Data replication and redundant storage can help recover files when a physical server becomes unavailable or experiences a hardware failure.

My confidence with the Linux command line has improved because I was able to perform several commands in the KillerCoda environment. I practiced using Docker, checking the status of a container, and working with a cloud storage service through the terminal and web interface. I still have more commands to learn, but this activity made me more comfortable following command-line instructions and understanding the purpose of the commands I use.
